## 3. 主要修复

### 鉴权与账号

- 所有学生、员工、后台接口均校验 token、角色、账号状态和 `token_version`。
- 五类角色已落库：学生、员工、管理员、维护人员、访客。
- 员工子角色已落库：顾问、班主任、领导，并按学生负责人/班主任/领导限制业务数据。
- 注册时保存加盐安全问题答案哈希，支持自助找回密码；管理员可重置员工密码。
- 浏览器可记住账号名；系统不保存或展示明文密码。
- 学生数据归属不再信任客户端 `student_id`，统一取当前 token 用户。
- GET 使用 `Authorization: Bearer`，不再把 token 放入 URL。
- 改密、重置密码、停用和启用均使旧 token 失效。
- 员工支持密码重置。
- 管理后台、心理预警、客户线索、成绩等敏感接口不再匿名开放。

### 核心业务

- 活动报名与留学申请完全分开；学生可从“申请进度”主动选择国家、学习模式和项目。
- 学生申请自动分配顾问，管理员在无顾问时兜底接收；申请状态从“待受理”开始。
- 请假支持明确起止日期、范围、中文数字、明天/后天/下周几和半天。
- 画像规则区分高中与中职，加入语言/动手能力条件和逐项目评分、排序、理由。
- 关注情绪只记录，≥70 才写预警；高危会通知在职员工。
- 心理画像可查询，最多保留 50 条历史。
- 售后详情可保存，解决工单会真正发送站内通知。
- NL2SQL 支持查询客户/成绩/日报/请假/投诉、审批请假、更新客户/投诉状态，并移除姓名 SQL 拼接。
- 活动报名使用事务、条件更新和部分唯一索引，已验证并发防超卖。
- 所有业务失败使用真实 HTTP 400/401/403/404/409/410/500。

### Dify

- “请假流程/怎么请假”等问题进入知识库，不再误写请假单。
- 员工客户查询、学生分数/学籍阶段、客服画像推荐均已真实联调通过。
- GET 工具通过 Authorization 头鉴权，POST 工具通过 body token 鉴权。
- 运行库工具数、工作流节点数、草稿与已发布版本均已对齐。
- 旧固定密码登录工作流已归档停用。

## 4. 使用

1. 后端已经运行在 `http://127.0.0.1:8000`。
2. 打开 `frontend/admin.html` 创建首个管理员。
3. 学生打开 `frontend/student.html` 注册。
4. 官网和客服页可直接打开。
5. 后续手动启动使用 `backend/start_server.ps1`；端口冲突时不会杀其他进程。

## 5. 边界

- 项目仍按原需求定位为单机演示/课程交付：SQLite、单后端进程、本机 Docker Dify。
- 知识库原文与向量数据由运行中的 Dify 管理；迁移到另一套 Dify 时需要重新导入知识库并替换本地 App Key。
- 学费、录取与政策最终以知识库和顾问确认的资料为准，系统不硬编码未经验证的费用承诺。
