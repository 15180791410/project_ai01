# 代码阅读指南

这份文档按“页面操作 → API → 业务逻辑 → 数据库”的顺序解释项目，第一次阅读代码时建议从这里开始。

## 1. 启动链路

1. `backend/main.py` 是 FastAPI 入口，注册所有路由、跨域、异常处理和健康检查。
2. `backend/db.py` 负责 SQLite 连接、建表迁移、索引和参考项目数据。
3. `frontend/index.html` 是官网，`student.html` 是学生端，`admin.html` 是员工/管理员/维护人员后台，`service.html` 是公开客服页。
4. 页面通过 `frontend/static/common.js` 调用 API；GET 使用 `Authorization: Bearer <token>`，POST/PUT 在 JSON body 中带 token。

## 2. 登录、密码和找回

- `backend/api/auth.py`：
  - `hash_password()` 使用 PBKDF2-SHA256 加盐哈希，数据库永远不保存明文密码。
  - `make_token()` 生成含用户 ID、角色、版本和过期时间的签名 token。
  - `current_user()` 每次请求都重新查库，因此停用账号、重置密码后可立即撤销旧 token。
  - `/register` 保存学生账号和安全问题答案哈希。
  - `/recovery-question` 返回账号设置的安全问题。
  - `/forgot-password` 校验安全问题答案后设置新密码。
  - `/staff` 只允许管理员创建员工、管理员和维护人员账号。
- 浏览器只记住用户名，不保存明文密码；密码应由浏览器密码管理器管理。

## 3. 五类角色

主账号类型 `sys_user.user_type`：

- `STUDENT`：学生。
- `EMPLOYEE`：业务员工。
- `ADMIN`：独立管理员。
- `MAINTAINER`：维护人员，只能查看运行状态。
- `CUSTOMER`：系统访客，无密码，不能登录。

员工子角色 `staff_role`：

- `ADVISOR` 顾问：默认只看自己负责的学生和客户线索。
- `HOMEROOM` 班主任：默认只看自己负责班级的学生、请假和预警。
- `LEADER` 领导：可以查看全部业务数据。

## 4. 活动报名和就读申请的区别

- `event_registration`：只表示报名参加讲座或活动，不代表申请留学。
- `application_progress`：正式的就读/留学申请。

学生操作：

1. 打开“申请进度”。
2. 选择国家/地区。
3. 系统根据国家筛选学习模式。
4. 系统根据模式筛选项目。
5. 提交后写入 `application_progress`，状态为“待受理”。
6. 优先分配给顾问；没有顾问时分配给管理员。
7. 顾问受理并推进阶段，学生可查看完整时间轴。

相关代码：

- `backend/api/application.py` 的 `/options`、`/apply`、`/advance`。
- `frontend/student.html` 的 `loadApplicationOptions()`、`syncApplyModes()`、`submitStudyApplication()`。

## 5. 学生端代码

- `backend/api/student.py`：请假、情绪、售后、成绩、心理画像。
- `backend/service/student_logic.py`：请假和售后数据库操作。
- `backend/utils/time_parser.py`：把“明天、三天、具体日期”转换成起止日期。
- `backend/service/emotion_logic.py`：关键词情绪分级、50 条画像历史、高危预警。
- `frontend/student.html`：学生页面，所有 API 请求的 `student_id` 都由后端 token 推导。

## 6. 员工端代码

- `backend/api/employee.py`：CRM、日报、成绩、NL2SQL。
- `backend/api/teacher.py`：请假审批。
- `backend/service/employee_logic.py`：客户模糊搜索、安全参数化 SQL、业务统计。
- `backend/api/lead.py`：官网留资自动分配线索。
- `backend/api/admin.py`：后台预警、客户、成绩总览。
- `frontend/admin.html`：根据账号角色显示不同菜单；维护人员不会加载业务隐私模块。

## 7. 推荐和 Dify

- `backend/service/rule_logic.py`：抽取年龄、学历、意向、语言和动手能力，再逐项目评分。
- `backend/api/recommend.py`：公开推荐工具。
- `docs/dify_dsl/build_tools.py`：从 FastAPI OpenAPI 生成 Dify 工具。
- `docs/dify_dsl/patch_workflows.py`：搭建学生、员工、客服工作流。
- `docs/dify_dsl/publish_runtime.py`：把工具和工作流写入本机 Dify。
- 业务 GET 工具必须传 `Authorization`；业务 POST 工具必须传 body `token`。

## 8. 数据表速记

- 用户与角色：`sys_user`
- 学生服务：请假、心理画像、预警、售后、成绩
- 员工运营：`crm_lead`、`employee_daily_report`
- 运营内容：`event_lecture`；留学方案和企业信息由 Dify Dataset API 实时读取
- 活动报名：`event_registration`（不是留学申请）
- 留学申请：`application_progress`、`application_history`
- 通知：`notification`
- 对话：`conversation_log`

## 9. 测试

- `backend/test_all.py` 会使用 `qa_*` 临时账号。
- 加 `--dify` 会真实验证三张 Dify 工作流。
- 测试结束后只删除本轮精确创建的数据，不清理其他真实业务。
