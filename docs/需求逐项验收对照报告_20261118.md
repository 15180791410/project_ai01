## 4. 架构对照

| 架构要求 | 当前实现 | 结论 |
|---|---|---|
| 学生/员工/客户多智能体 | Dify 三张工作流 | 符合 |
| LLM 编排与知识库 | Dify 负责意图、检索、回答 | 符合 |
| Python 业务后端 | FastAPI + service 层 | 符合 |
| Dify 不直接访问 SQLite | 全部通过 HTTP 工具调用 FastAPI | 符合 |
| SQLite 持久化 | 21 张业务表 | 符合；知识库方案与公司信息不在后端落库 |
| 四个知识库整合 | 业务事实统一使用“ai知识库” | 符合用户说明 |
| 可解释推荐 | 确定性规则 + 匹配度 + 来源文档 | 符合 |
| 心理预警 | 后端评分、落库、通知 | 符合 |
| 可追溯 | 申请时间轴、通知、操作员字段 | 超出文档要求 |
| 安全 | 登录、PBKDF2、令牌版本、RBAC、数据范围 | 超出文档要求 |

当前 Dify 运行库：

- ai业务知识库：1 个。
- 自定义工具：50 个；留学方案只有 Dify 实时读取，没有后端写入工具。
- 学生工作流：草稿与发布均为 48 节点 / 47 边，15 个分类（14 业务 + 1 兜底）。
- 员工工作流：草稿与发布均为 34 节点 / 33 边。
- 客服工作流：草稿与发布均为 19 节点 / 18 边，5 个分类（4 业务 + 1 兜底）。

## 5. 本次审计发现并修正

1. `/api/health` 需求路径缺失，已增加兼容路由，同时保留 `/health` 探针。
2. 学生/员工 Dify 图存在重复节点 ID，Dify 草稿会自动去重导致草稿与发布不一致；生成器已改为共享节点去重。
3. 删除停用旧报名接口、重复画像测试接口、旧兼容函数和未使用的时间解析函数。
4. 删除旧 Dify 草稿、一次性样式工作区、重复数据库快照、Python 缓存和过时文档。
5. 修正文档中的接口、表数量和工作流节点数量。

## 6. 仍需注意

- 项目定位仍是课程/演示级单机架构，SQLite 和单后端进程不适合直接作为高并发生产系统。
- Dify 使用真正的 `question-classifier` 节点进行语义分流；后端确定性兜底仍保留，用于关键业务防误判。
- 前端可通过 `frontend/start_frontend.ps1` 使用 8080 独立静态服务，与 8000 FastAPI 解耦。
- FR-017、FR-025 已补齐独立详情接口；后续如增加分页，可再扩展列表参数。
- 公司和方案事实始终以 Dify“ai知识库”为准；后端不保存 `company_content`、`course_project` 副本。
