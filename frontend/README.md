# ai智能平台 · 前端说明（企业级 v6）

## 页面结构（官网 + 三类服务入口）

| 页面 | 入口 | 面向谁 | 登录要求 | 功能模块 |
|---|---|---|---|---|
| `index.html` | 企业官网首页 | 所有人 | 无 | 知识库来源公司介绍 / 服务范围 / 留学方案 / 最新活动（**可报名**）/ 留资表单 / 联系页脚 |
| `student.html` | 学生工作台 | 留学生 | **需注册登录** | 概览 / 智能助手 / 请假申请 / 我的请假 / 售后反馈 / 我的成绩 / **活动报名** / **申请进度时间轴** / 心情记录 / 用户中心 / **通知中心** |
| `admin.html` | 管理后台 | 按角色显示不同菜单 | **员工账号登录** | 管理员可管理内容与账号；顾问处理本人 CRM/申请/售后；班主任处理本班请假/预警/售后；领导查看和推进业务数据；维护人员只看运行状态 |
| `service.html` | 客服与活动 | 访客/家长 | **免登录** | 在线咨询 / 留资给顾问（进入 CRM） |

> 旧的 `login.html` / `chat.html` / `teacher.html` 三个纯重定向页已在 2026-11-17 目录清理中删除；三个服务入口统一由 `index.html` 提供。

### v3 升级要点（本次）
1. **官网首页**：关于我们、企业资料、服务体系、留学方案、活动、留资和页脚。留学方案与企业资料从 Dify 实时读取；活动由后台运营人员维护。
2. **老师模块并入员工后台**：老师与员工同为公司服务人员，功能合并，保留员工一个角色。请假审批、学生名单、心理预警全部整合进 `admin.html`（原 `teacher.html` 已删除）。
3. **情绪预警链路修复**：以前只有「心情记录」页写预警表，学生在**智能助手聊天**里倾诉高危情绪时老师看不到预警。现在两条通道都做混合检测：后端关键词和危险组合规则优先，Dify 安全回复作为语义兜底；已入学学生写入心理画像，咨询期/申请期只保留必要的安全预警而不写心情历史。最终分数、预警落库与通知对象由后端决定，并做 10 分钟去重。
4. **审批留言 / 驳回理由**：老师通过请假时可附一句留言，驳回时**必须填写理由**；学生在「我的请假」里能看到老师的留言或驳回理由。
5. **内容配置**：活动和留学方案只允许管理员新增、编辑、删除；领导可只读查看业务数据。
6. **Dify 思考过程过滤**：后端自动过滤模型泄漏的 `<think>...</think>` 标签，聊天框不再显示思考过程。

### v4 升级要点（本次：打通真实业务闭环）
1. **官网留资 → 客户线索**：官网 CTA 表单填写姓名/联系方式/意向国家，直接写入 `crm_lead`，自动分配给线索最少的员工并通知其跟进；员工后台「客户线索」可更新销售阶段、追加跟进记录。
2. **活动报名闭环**：官网/学生端活动卡片可在线报名（防重复、名额限制、满额禁报），报名写入 `event_registration` 并回写名额；匿名访客报名会按联系方式复用或新建 CRM 线索、自动分配顾问并回填 `lead_id`，顾问可在「活动与报名」查看本人负责的名单并直接跟进；学生端「我的报名」可追踪。
3. **留学申请进度时间轴**：新增 `application_progress` / `application_history` 表。员工为学生建档并推进八阶段（选校→材料→递交→面试→Offer→签证→行前→入学），每步留痕；学生端「申请进度」以时间轴 + 进度条可视化展示。
4. **站内通知中心**：新增 `notification` 表。审批结果、预警处理、活动报名成功、申请阶段更新都会主动推送到学生/员工的通知铃铛，支持未读角标、单条/全部已读。
5. **公司事实来源**：官网和员工端涉及公司的内容只使用 Dify ai知识库数据；后台保留来源追踪，但前端不展示来源文档、检索时间或相似度等技术标记。

### v5 全角色权限升级

- 管理员：全部业务、内容配置和账号管理，并可一次登录切换所有演示视图。
- 员工账号类型统一下包含顾问、班主任、领导三个 `staff_role`，不是三个独立账号类型。
- 员工·领导：全部业务查看与推进，但不能修改活动，也不能管理账号；方案只读 Dify。
- 员工·顾问：本人客户线索、本人负责学生、申请和成绩；预警只读，不处理请假或预警。
- 员工·顾问：本人客户、本人学生申请/成绩/售后，预警只读；班主任：本人班级请假、预警、售后和成绩；两者都不管理账号和内容配置。
- 维护人员：只能查看运行状态和本人账户，不读取学生、客户、请假、成绩或预警。
- 所有限制均在 FastAPI 后端强制校验，前端菜单和按钮隐藏只是体验层。
6. **自动数据库迁移**：`db.py` 的 `ensure_migrations()` 启动即执行建表（幂等），老库自动获得新表新列，无需手动改库。

### v6 数据可视化与统一视觉层

- `static/premium.css`：统一官网、学生端、员工端和客服端的视觉语言，采用玻璃卡片、运营驾驶舱头图、深色渐变侧栏和响应式布局。
- `static/charts.js`：项目内置原生 SVG/CSS 图表组件，不依赖外部 CDN；提供环形图、横向柱状图、阶段分布图、趋势线、进度条和组织/流程树。
- 员工工作台：客户阶段分布、学生国家分布、心理预警等级、申请阶段、成绩区间、活动容量及角色业务协同树。
- 学生工作台：课程成绩、服务构成、申请阶段、情绪趋势、活动余量和留学流程可视化。
- 官网与客服页：服务链路、角色能力和咨询处理路径树状展示。
- 所有运营图表只使用当前角色有权读取的 SQLite 业务数据；公司介绍、费用、政策和项目内容仍只来自 Dify 知识库。
- `audit_visual.js` 可用无头 Edge 验证图表挂载、运行时错误和四个页面截图，输出到 `docs/visual_*.png`。

## 快速开始

### 1. 启动后端（每次改了 Python 代码都要重启）
```powershell
cd C:\Users\Windows\Desktop\yuejiao_project\backend
.\start_server.ps1
```
脚本会先检查端口；若 8000 被占用则安全退出，不会强制结束其他进程。可用 `.\start_server.ps1 -Port 8001` 换端口。
若提示安全策略，先执行：`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`

> ⚠️ **本次 v4 新增了 `/api/lead`、`/api/application`、`/api/notification` 等接口，必须重启后端才会生效！**
> 验证：浏览器打开 `http://127.0.0.1:8000/openapi.json`，应能看到 `/api/content/events/register`、`/api/lead/submit`、`/api/application/my`、`/api/notification/list` 等路径。启动时数据库会自动建好申请进度表、通知表。

### 2. 打开前端
通过 FastAPI 同源地址访问，不要直接双击 HTML 文件：

- 官网：`http://127.0.0.1:8000/`
- 员工后台：`http://127.0.0.1:8000/admin.html`
- 学生工作台：`http://127.0.0.1:8000/student.html`
- 客服：`http://127.0.0.1:8000/service.html`

稳定的 HTTP 域名是浏览器密码管理器保存密码的前提。

### 3. 首次初始化（无内置账号）
- **管理员**：打开 `admin.html`，系统检测到库里没有员工账号时会显示「首次初始化」，填账号 + 至少 8 位密码即可创建并进入后台。后续同事在「用户中心 → 员工账号」里开通。
- **学生**：在 `student.html` 自行注册（账号 ≥3 字符、密码 ≥6 位），注册即登录。
- **客服与活动**：`service.html` 免登录，走系统访客账号，不占用真实账号。

## 核心业务闭环

### 请假 → 审批 → 留言反馈
```
学生端 student.html
  └─ 请假申请（起止日期 + 理由）→ POST /api/student/leave
  └─ 我的请假 → GET /api/student/my_leaves（状态 + 老师留言/驳回理由）
                          ↓ 状态共享
员工后台 admin.html
  └─ 请假审批 → GET /api/teacher/pending-leaves（带学生姓名）
  └─ 通过（可附留言）/ 驳回（必填理由）→ POST /api/teacher/approve
  └─ 学生端刷新即可看到审批结果与留言
```

### 情绪 → 预警 → 处理
```
学生端（智能助手聊天 OR 心情记录）
  └─ 输入含高危/关注情绪的词 → 后端 emotion_logic 检测
  └─ 自动写入 student_psych_alert（10分钟去重，附学生姓名）
                          ↓
员工后台 admin.html
  └─ 心理预警看板 → GET /api/admin/alerts（实时）
  └─ 标记已处理（可填处理备注）→ POST /api/content/alert/handle
```

### 官网留资 → 线索跟进（v4 新增）
```
企业官网 index.html（免登录）
  └─ CTA 表单填姓名/联系方式/意向国家 → POST /api/lead/submit
  └─ 自动分配给线索最少的员工 + 通知该员工
                          ↓
员工后台 admin.html
  └─ 客户线索 → GET /api/lead/list
  └─ 跟进（更新阶段 + 追加记录）→ POST /api/lead/follow-up
```

### 活动报名（v4 新增）
```
官网 index.html / 学生端 student.html
  └─ 点活动"报名" → POST /api/content/events/register（防重复+名额校验）
  └─ 学生端"我的报名" → GET /api/content/my-registrations
                          ↓
员工后台 admin.html
  └─ 活动管理 → 点"名单" → GET /api/content/events/registrations
```

### 留学申请进度（v4 新增）
```
员工后台 admin.html
  └─ 申请进度管理 → 新建申请 POST /api/application/create
  └─ 推进阶段 POST /api/application/advance（每步留痕 + 通知学生）
                          ↓
学生端 student.html
  └─ 申请进度 → GET /api/application/my（时间轴 + 进度条，实时可见）
```

### 站内通知（v4 新增）
审批 / 预警处理 / 活动报名 / 申请进度更新 → 自动写 notification 表
  → 学生与员工顶部铃铛显示未读角标 → 点击展开 → 单条/全部已读

## 安全设计
- **学生注册**：真实密码，PBKDF2-SHA256 加盐哈希存储。
- **角色隔离**：学生、员工和后台接口均在服务端校验角色、账号状态和 `token_version`；学生业务的数据归属直接取当前 token，不再信任客户端传入的 `student_id`。
- **审批守卫**：请假查看和审批只允许班主任、管理员、领导；班主任还必须满足班级归属。
- **内容管理守卫**：活动和留学方案的写操作仅管理员可用；其他角色与访客只读取知识库已确认内容。
- **全角色权限矩阵**：功能权限由 `backend/service/rbac.py` 集中定义，接口同时校验角色权限与记录归属。
- **改密码**：校验原密码后才允许修改。
- **访客隐私**：客服访客数据仅存 sessionStorage，不上传服务器。

## 后端接口总览

### `/api/auth`（认证与用户中心）
`register` / `login` / `me` / `profile`（含意向国家）/ `change-password` / `users` / `verify-admin` / `dify-chat`（含学生情绪检测）/ `public-chat`

### `/api/teacher`（请假审批，已并入员工后台）
`GET /pending-leaves` / `GET /all-leaves` / `POST /approve`（通过附留言、驳回必填理由）

### `/api/content`（内容管理，v3 新增）
| 接口 | 说明 |
|---|---|
| `GET /events` / `POST /events/save` / `POST /events/delete` | 活动管理（读公开、写仅员工） |
| `GET /programs` | 从 Dify 实时读取留学方案；不存在后端新增/编辑/删除接口 |
| `POST /student/country` | 学生设置意向国家 |
| `GET /students-by-country` | 按意向国家分组的学生（仅员工） |
| `POST /alert/handle` | 处理心理预警（仅员工） |
| `POST /events/register` | 活动报名（学生或访客，防重复+名额校验） |
| `GET /events/registrations` | 活动报名名单（仅员工） |
| `GET /my-registrations` | 我的报名（学生） |

### `/api/lead`（客户线索，v4 新增，读为员工）
`POST /submit`（官网留资，公开）/ `GET /list`（线索列表）/ `POST /follow-up`（更新阶段 + 跟进记录）

### `/api/application`（申请进度，v4 新增）
`GET /my`（学生看自己的）/ `GET /all`（员工看全部）/ `POST /create`（员工建档）/ `POST /advance`（推进阶段）

### `/api/notification`（通知中心，v4 新增）
`GET /list`（列表+未读数）/ `GET /unread`（未读数）/ `POST /read`（单条或全部已读）

### 业务接口（沿用）
- 学生：`/api/student/*`　员工：`/api/employee/*`　客服：`/api/customer/*`　后台：`/api/admin/*`

## 系统架构（标准流程）

```
                        ┌──────────────── Dify ────────────────┐
 index/前端页面         │                                      │        后端
 用户输入 ──请求──────► │  学生工作流 ─┐                        │
   │                    │  员工工作流 ─┼─ 通过「工具」调用 ───► │  各种 API 接口
   │                    │  客服活动流 ─┘  (自定义工具与接口一一对应)
   │                    └──────────────────────────────────────┘
   │
   └── 后台管理（admin.html）──── 直接调用后端 API，不经过 Dify 编排 ────►
```

**两条链路，边界清晰：**

| 场景 | 走向 | 说明 |
|---|---|---|
| 首页「问一问」/ 学生智能助手 / 员工助手 / 客服咨询 | 前端 → 后端代理 → **Dify 工作流** → 工具 → 后端 API | 自然语言理解与多轮对话交给 Dify |
| 后台管理：请假审批、活动管理、客户线索、申请进度、报名名单、心理预警 | 前端 → **直接调用后端 API** | 留学方案与企业信息必须从 Dify 实时读取 |

**身份路由（首页统一入口）**：`index.html` 的提问框按登录态自动分流——
访客 → 客服与活动工作流（`public-chat`）；已登录学生 → 学生工作流；已登录员工 → 员工工作流（`dify-chat`）。

> 工作流里放的是**对话场景需要的能力**：学生端提交请假/情绪/反馈 + 查询成绩/请假/申请/报名/通知；

## 前端访问地址

页面由 FastAPI 同源托管，推荐统一使用 `http://127.0.0.1:8000/`。
直接双击 `file://` 页面仍可打开，但浏览器密码管理器通常不会保存密码；
该模式只作为兼容旧演示方式的备用入口。

## 常见故障
- **新接口报 404 / 官网方案活动不更新**：后端没重启，仍是旧代码。重跑 `start_server.ps1`，确认 `/openapi.json` 有 `/api/content/*`、`/api/lead/*`、`/api/application/*`、`/api/notification/*`。新表（申请进度/通知）会在后端启动时自动建好。
- **注册/门禁/客服报 404**：确认页面是通过 `http://127.0.0.1:8000/` 打开，
  且后端 8000 端口正常。
- **Dify 聊天超时**：确认后端监听 `0.0.0.0`、工作流已发布，并检查本地 `dify_config.local.json` 或环境变量中的 Key。
